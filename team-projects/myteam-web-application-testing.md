# MyTeam Web Application – Team Testing Project

## Project Overview

This was a team-based web development project completed during my Software Testing studies at TECHIN.

The team developed a responsive multi-page website based on provided design requirements. My main responsibility in the project was software testing and quality assurance.

The completed project was presented to the instructor as the final team project.

**Original team repository:**  
https://github.com/kestas121/figma-project

## My Role

**Software Tester / QA**

My responsibility was to verify implemented functionality and UI, identify defects, communicate issues with developers and perform retesting after fixes.

## Testing Scope

I tested the application across desktop, tablet and mobile layouts.

The main testing areas included:

- UI testing
- Responsive testing
- Functional testing
- Figma/design comparison
- Layout and alignment checks
- Text wrapping and spacing
- Navigation behaviour
- Scrolling and horizontal overflow
- Cross-section consistency
- Retesting after bug fixes
- Regression checks

## QA Workflow

The project followed a branch-based Git/GitHub workflow.

My typical testing process included:

1. Fetching the latest repository changes.
2. Switching to the development branch assigned for testing.
3. Running the project locally.
4. Testing the implemented feature or section.
5. Comparing the implementation with the provided design.
6. Checking desktop, tablet and mobile layouts where required.
7. Reporting confirmed defects in Jira.
8. Communicating minor visual inconsistencies directly with developers when a Jira bug was not necessary.
9. Retesting fixes after developers updated the implementation.
10. Performing regression checks before the work was considered complete.

## Defect Reporting

During the project I created **6 Jira bug reports** for confirmed issues.

Reported defects included UI, layout and responsive behaviour problems.

Smaller visual differences were sometimes communicated directly to developers instead of being registered as separate Jira bugs, according to the team's agreed workflow.

Bug reports included information such as:

- Clear summary
- Description
- Steps to reproduce
- Expected result
- Actual result
- Priority
- Related task / development branch
- Supporting screenshots where useful

## Responsive and UI Testing

A significant part of my work focused on verifying whether the implemented pages matched the provided designs at different screen sizes.

Testing included:

- Desktop layouts
- Tablet layouts
- Mobile layouts
- Element positioning
- Text alignment
- Spacing
- Section dimensions
- Content wrapping
- Horizontal overflow
- Footer and navigation behaviour

Chrome DevTools was used to test specific viewport sizes.

Pixel Parallel was also used to overlay design screenshots over the implemented website to identify visual differences more precisely.

## Git and Branch Testing

I used Git and GitHub as part of the QA workflow.

Typical commands and actions included:

- `git fetch --prune`
- `git branch -r`
- `git branch -a`
- `git switch`
- `git pull`

Individual development branches were tested before changes were merged into the main project branch.

This gave me practical experience working in a development workflow where QA testing was integrated with Git branches and team collaboration.

## Team Collaboration

The project was completed as a team.

During testing I communicated directly with developers about identified issues, clarified visual differences and verified fixes after changes were made.

This project helped me practice not only finding bugs, but also deciding when an issue should be formally registered in Jira and when a small visual inconsistency could be communicated directly to the developer.
